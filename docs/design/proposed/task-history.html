Display and retention model

Default presentation

Newest-first narrative stream, grouped by calendar day. Events use short sentences, explicit actors, semantic icons, and exact timestamps. This is easier to reconstruct than a field-oriented table.

Source ownership

Mission Control does not clone a provider's complete audit log. GitHub remains authoritative for comments, reactions, label edits, and its issue timeline. Microsoft Todo, Planner, and future sources follow the same rule according to their capabilities.

What MC stores

Persist MC-only decisions and cross-system facts: project and phase placement, My Day, planning horizon, local disposition, delegation, linked-source reconciliation, source sync outcomes, and the source milestones required to explain current MC state.

Source milestones

Mirror only consequential provider changes that affected the MC task, such as opened, closed, reopened, transferred, deleted, or authoritative field changes. Each record carries provider provenance and a deep link to the native event where available.

Initial limit

Render the newest 20 meaningful events. Load earlier events in pages of 20. Always show total captured count and the oldest available boundary so progressive disclosure never looks like complete history.

Noise collapse

Collapse consecutive low-information automation events by source and day. A rollup says exactly how many events and what time range it covers; expansion reveals every underlying record.

Filters

All, MC Changes, Planning, Delegation, and Source. This first separates what Mission Control owns from what it observed elsewhere, then groups MC-only activity by user intent. Search is deferred until histories routinely exceed hundreds of meaningful entries.

Text changes

Summarize title or description edits by default. “View change” opens a focused before/after diff. Do not place long prose or raw JSON directly in the stream.

Delegation overlap

Show task-level milestones only: delegated, waiting for input, failed, cancelled, PR ready, completed. “View run details” opens the execution timeline with attempts, provider events, artifacts, checks, and controls.

System provenance

Every event names an actor or source: the user, another person, connector, automation, or delegated agent. Raw IDs remain behind a detail affordance, not in primary copy.

Capture boundary

Never imply pre-capture history exists. End the stream with a plain boundary statement such as “MC history begins Sep 28.” Keep a separate link to the source's older or more complete native history.

Event vocabulary

Changes

Status, priority, field edits, recurrence, disposition, and relationship changes.

Planning

Project, phase, My Day, planning horizon, due date, effort, and schedule changes.

Delegation

Delegated runs, MC-owned assignments, approvals, handoffs, and linked outputs. Provider-native discussion stays at the source.

Source

Consequential provider milestones and sync reconciliation, clearly attributed and linked back to the authoritative system.

Outcomes

Completion, accepted results, pull requests, restored sync, and other terminal milestones.
