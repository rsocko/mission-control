Document Intelligence — Triage Gallery Cards
This mockup shows how DocIntelligence action queue items surface as document content-type cards in the existing Triage Gallery view. The document branch in GalleryCard follows the same pattern as the existing repo and text_post branches — no thumbnail image, structured metadata in the card area.
Zero source-checking in the renderer. The card shape is selected by contentType === 'document' — a generic content type, not by sourcePlatform === 'document-intelligence'. Any future connector that provides document content simply sets the same content type and gets the same card treatment. The source badge (📄 DOCS) is rendered by the existing SOURCE_META map just like Reddit/GitHub badges.

Card anatomy & implementation spec
Element Location Value source Notes
Source badge Top-left SOURCE_META['document-intelligence'] Same map as reddit/github/youtube. Label: "Docs", icon: fa-file-lines. Uses existing badge renderer.
Score badge Top-right item.aiRelevanceScore Existing getScoreColor() helper. Urgency-based for documents: critical=95, high=80+.
Action type chip Bottom of thumb, left item.rawMetadata.actionType New element specific to contentType === 'document'. Color-coded by action type. Replaces play-button overlay used by video cards.
Priority dot Bottom-right of thumb item.rawMetadata.urgency Small dot indicator. Critical = red glow. Provides at-a-glance urgency without text.
Quick actions Hover overlay, bottom item.aiSuggestedActions[0] → primary Uses existing QuickActions component. Primary action maps from action type: pay→complete, sign→sign, file→file, review→complete. Adds open_document action type.
Line-art background Full thumb area Static / decorative Simulates document lines. Opacity 0.25. Gives visual texture without requiring a real thumbnail. Tinted by action type color.
Title Card info, primary item.title Built from DocIntelligence document_title. 2-line clamp.
Correspondent / date Card info, left of amount item.rawMetadata.correspondent or due date Shows correspondent name when available; falls back to due date with clock icon. Red if overdue.
Amount Card info, right item.rawMetadata.amount Green normally; red if overdue/critical. Page count shown for non-financial docs.
Type system additions (src/types/index.ts)
Type Addition Rationale
TriageContentType 'document' Generic document content type. Any connector (not just DocIntelligence) can set this. Drives the document branch in GalleryCard.
TriageSourcePlatform 'document-intelligence' Enables source filtering in the Triage page and SOURCE_META badge lookup.
TriageActionType 'complete_action' 'open_document' 'defer_action' complete_action: marks action done in DocIntelligence. open_document: opens in Paperless. defer_action: equivalent to snooze but semantically tied to action items.
Connector changes (document-intelligence/index.ts)
Change Detail
Add 'file' + 'review' to TASK_ACTION_TYPES Currently these two action types are silently dropped. Both should become tasks with their own title builders: "File: [doc]" and "Review: [doc]"
Populate metadata.previewUrl + previewType Set metadata.previewUrl = action.document_url and metadata.previewType = 'external' (or 'pdf' when Paperless iframe embedding is available). TaskDetailPanel uses this generically.
metadata.previewLabel Human-readable button label: "View in Paperless". Used by the generic preview section in TaskDetailPanel.
Optional: TriageItem bridge Add a fetchTriageItems?() optional method to IConnector that returns TriageItem[]. DocIntelligence implements it to surface action queue items in the Triage queue. This keeps Triage integration opt-in per connector.
