User Customization: Pin & Reorder

Should users be able to rearrange nav items or should the app auto-adapt based on usage?

🔬 Industry Research

Auto-rearranging is widely discouraged. Microsoft tried adaptive menus in Office 2003 (hiding infrequent items) — it was so disliked they reverted it entirely. Studies consistently show that unexpected nav changes destroy muscle memory and hurt returning/power users the most.

User-initiated customization is the safe middle ground. Apps like Slack (sidebar sections), iOS (tab bar customization), and Figma (starred projects) let users choose what to surface — but the default layout stays stable.

Suggested approach for Mission Control: Don't auto-rearrange. Instead, consider a future "pin to nav bar" gesture where a user can drag an overflow item (e.g. Triage) up to the visible nav. This is opt-in and preserves muscle memory.

Verdict: Trigger D (dual active state) is standard practice. Every major app with nav overflow highlights both the "More" button and the item inside the dropdown. This is not optional — it's expected UX. Our proposed accent tint + underline on "More" matches GitHub's exact approach.
