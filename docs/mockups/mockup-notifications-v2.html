Revised interaction mockup

Notifications that lead somewhere

The side panel is a quick attention queue, not a compressed version of the full inbox. It keeps choices small, makes the next action visible, and uses a real preview when an item is selected.

1. Make the CTA unmistakable

Actionable items always expose one verb-specific button: Review PR, Reconnect, Track package. Read, snooze, and dismiss stay secondary.

2. Selection opens a preview

Clicking a row marks it selected and opens a larger anchored preview with full context and actions. It never merely loosens text spacing.

3. Show priority before state

The panel restores level counts for at-a-glance triage. Unread and actionable become independent refinements; source filtering, search, and deeper compound filters remain on the full page.

Mockup A: dashboard quick panel

Click a notification to see the selected state and anchored preview. Combine a level with the unread and actionable refinements.

Pattern rationale

The recommendation combines familiar inbox behavior without copying any one product wholesale.

Borrow from GitHub

Notifications are a work queue with clear unread state, reasons, grouping, and a path to a fuller inbox for advanced filtering.

Borrow from Linear

Selection opens a meaningful detail view; quick search and display controls belong in the dedicated inbox rather than crowding every surface.

Preserve Mission Control familiarity

The full notification center keeps its existing left navigation for level, category, source, and state. Search and sorting remain in the header.

Borrow from commerce/community apps

Use concrete verbs tied to the event: Track package, View order, Reply, Review, Reconnect. Avoid generic Open CTAs.

Do not borrow

Do not turn the dashboard panel into a filter-heavy management console, hide the intended action in an overflow menu, or expand a row without revealing new information.
