Selective review

A compact field table makes the bundle legible and turns every suggestion into an independent decision.

Why it works

  • Selection and editing are separate, visible actions.
  • Project ranks suggested matches above a searchable full list; phase is always scoped to that project.
  • Changing project clears phase immediately, then re-evaluates and preselects only a new high-confidence match.
  • Tags are removable one by one and can be searched or created inline; #tag remains the fastest capture syntax.

Tradeoff

  • Tallest option; best after creation rather than during rapid typing.
  • Five or more suggestions need strong ordering and a compact overflow pattern.

Smart chips

The existing suggestion language becomes interactive: each chip is both an inclusion toggle and a doorway to edit or evidence.

Why it works

  • Smallest footprint and easiest to scan in the existing toast.
  • Selected state replaces the current green-on-green treatment with blue action semantics.
  • Project and phase evidence stays progressive rather than permanently visible.
  • Each tag is its own chip, so removing one never discards the others.

Tradeoff

  • A chip has two jobs: toggle and edit. The internal “Change” target must remain distinct.
  • Less suitable when the system needs to explain a surprising match.

Evidence review

A field list and dedicated explanation pane make project and phase inference inspectable, including whether an existing rule will already act.

Why it works

  • Best expression of source affinity, exact/fuzzy title match, semantic match, and project rules.
  • Makes confidence understandable through evidence rather than a naked score.
  • Supports future “Always use this match” or rule-management actions.

Tradeoff

  • Too heavy for every successful quick entry.
  • Best reserved for low-confidence or conflicting project/phase suggestions.
  • Tags remain individually removable even when the evidence view is open.
